# Step 1 · Set the job

Name who the screen is for, the job and the moment, before designing anything.
A screen built for nobody in particular gets built for the average, and the average is slop.

## Skip what's already answered

- **The model already asked its own questions** and the user answered: reuse those answers. Ask nothing new.
  Ask only if "who" or "the job" is still missing.
- **`team-rules.md` names the product and its users:** reuse that. Ask only what's specific to this screen.
- **Fast mode** (only when the user said "just build it" or "don't ask"): don't ask. Use your guesses and mark them "(assumed)".
- **No question tool?** Ask anyway: write the questions in your reply and stop.

## Guess first

Read the screenshot, the screen's code or the conversation, and guess each answer.
A guess is a ready answer for the user to confirm, never a fact.

## Ask once, all together

Send one message with all six questions, each pre-filled with your guess:

> Before I change anything, six quick answers. My guesses are filled in, so fix any that are wrong.
> 1. **Who uses it?** {guess: a role and their situation}
> 2. **The job:** what must they get done here? {guess}
> 3. **The moment:** when, where, on which device? {guess}
> 4. **Not for:** who shouldn't this screen serve? {guess}
> 5. **Must have:** what has to stay, or be one click away? {guess}
> 6. **How we'll know it worked:** {guess, something you can see on the screen}

- Ask once. Don't drip the questions one by one.
- Keep each guess to one line.
- If the user answers only some, use your guesses for the rest and mark them "(assumed)".
- Wait for the reply before designing, unless you're in fast mode.

## Good answers

| Question | Weak | Strong |
|---|---|---|
| Who | "users" | "a designer in the middle of a job search" |
| The job | "manage interviews" | "see what to practise next and start it in one click" |
| The moment | "anytime" | "evenings after work, on a laptop, interview tomorrow at 11 am" |
| Not for | (blank) | "recruiters and investors, so no industry comparisons" |
| Must have | "everything" | "the next practice is one click from the dashboard" |
| Worked | "looks clean" | "the next practice is the first thing on the page" |

"Not for" removes whole kinds of slop at once: comparisons with other people, made-up targets, marketing numbers.

## Keep the answers

Keep all six answers for the rest of the run. Steps 3 and 4 check every widget and every number against them.

## Report: fill these keys

- `for`: one line, "who, when · the job".
  Example: "a designer job-hunting, evenings on a laptop · see scores, practise next in one click".
  Add "(assumed)" after any part you guessed.
- `steps.job`: "done".
